# CLSR offline tools: tests and strategy benchmark

These tools compile the game's own engine-independent rules (`Assets/Scripts/Core`) without
Unity. The game and these tools therefore share one implementation of legality, resolution
and visibility. Requires the .NET 8 SDK and nothing else (no NuGet packages).

```sh
cd Tools/CLSR.Offline
dotnet run -c Release -- test    # automated tests (simulation, visibility, research integrity, HUD geometry, agents)
dotnet run -c Release -- eval    # benchmark strategies; writes results/benchmark.md and results/runs.csv
dotnet run -c Release -- eval --variants 200
```

The test command also runs the backend's Python request validator (`backend/support.py`) on
payloads generated by the C# builder, when `python3` is on the PATH.

## What is shared with the game

| File | Role |
| --- | --- |
| `Core/ScenarioSpec.cs` | Ground-truth scenario (converted from `RescueScenarioData`), validation |
| `Core/RescueSimulation.cs` | The only place plans are validated and days are resolved; hidden state |
| `Core/PublicView.cs` | Player-visible projection; unrevealed values are `null` |
| `Core/SupportSnapshot.cs` | `rescue-support-v2` AI request body, built from `PublicView` only |
| `Core/ResearchLog.cs` | Event log format and the protocol timing constants |
| `Core/MapViewMath.cs`, `Core/TacticalLayout.cs` | Camera zoom math and HUD regions (presentation only) |

`ScenarioController` and `RescueGameController` in Unity are thin wrappers around these.

## Agents

Agents receive only a `PublicView` and must return a plan that passes the simulation's
`Validate`. They never see the scenario. See `Agents.cs` and the strategy table in
`results/benchmark.md`. Reinforcement learning is not included: the questions here
(is the scenario trivially solved, do strategies trade off) are answered by search and
heuristics, and the exact full-information optimum (`OracleSolver`) already gives a ceiling.

Variants re-place each branch's true survivors at random while keeping the map, thresholds,
caches and reports, to check that conclusions are not an artefact of one placement.
None of these agents is a participant-facing AI condition.

## Findings (100 variants per map, generated 2026-11-22)

- **No simple rule dominates across the two study maps.** On Blackridge, `cache-aware` beats
  `greedy-rescue` on 76 of 101 variants (+1.50 survivors on average). On Cedar Valley it loses
  to greedy on 59 of 101 (-0.57). Investing in storage pays on one map and not the other.
- **Greedy is strong but far from solving the maps.** It reaches about 65–71% of the
  full-information optimum on the study maps, against 36–38% for random legal play. The gap to
  the oracle (about 2.5 survivors on Cedar Valley, 5 on Blackridge) comes from hidden placement
  and thresholds, which no public-information policy can fully close.
- **Day 1 is decisive.** On the authored Blackridge map only 5 of 991 legal Day-1 plans keep the
  optimum of 11 reachable. On Cedar Valley, 20 of 785 keep the optimum of 9 reachable.
- **More computation did not help reliably.** The hindsight `lookahead` planner is marginally
  better than greedy on Cedar Valley (+0.28, SE 0.16) and clearly worse on Blackridge (-1.50).
  It assumes it will know everything tomorrow, so it waits or over-explores. This is the
  usual weakness of hindsight optimisation, not evidence that the map rewards waiting.
- **Exploration for its own sake is costly.** `explorer` reveals the most thresholds but loses
  about 9 points on blocked teams on Cedar Valley and rescues fewer people.

Reading: the maps present real trade-offs (rescue now vs. invest in storage vs. scout), and
the best simple policy depends on the map. That suits a decision-making study. It is not an
argument that a trained agent is needed.
